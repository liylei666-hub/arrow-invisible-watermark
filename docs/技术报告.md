## 三、核心原理

### 3.1 差分宽度调制（Manchester 思想的空域版）

每个 bit 占用**相邻两个码元**（一个差分对）。在一个码元内，把笔画沿水平方向整体加宽 +d 或收窄 −d：

```
bit = 1  →  码元 A 宽(+d)  |  码元 B 窄(−d)
bit = 0  →  码元 A 窄(−d)  |  码元 B 宽(+d)
```

判决量是**两者的相对差**：

```python
d = w_A - w_B        # d > 0 → bit 1，否则 bit 0
conf = d / (w_A + w_B)
```

这样设计的价值在于抵消全局性信道失真：

| 失真类型 | 对 w_A 的影响 | 对 w_B 的影响 | 差分后 |
|---|---|---|---|
| 油墨整体偏浓/偏淡 | +g | +g | 抵消 |
| 烧制整体膨胀/收缩 | +g | +g | 抵消 |
| 全局曝光变化 | ×k | ×k | 抵消（符号不变） |
| 高斯模糊 | 半高宽不变 | 半高宽不变 | 抵消 |
| 环境光渐变 | 局部近似相等 | 局部近似相等 | 抵消 |

> 注意：这里调制的是**水平截宽**。用水平线状结构元做膨胀/腐蚀，无论笔画是竖直还是斜的，水平宽度都精确变化 2d，且不改变笔画的纵向长度——这使得斜笔画（A 的腿、W 的对角线）也能直接复用同一套测量逻辑。

### 3.2 码元布局的自动推导

不手工切格子，而是从字形掩膜自动推导，流程如下：

1. **逐行求墨迹游程**：`run = (start, end)`，一行可能有多段（如 A 的两条腿）。
2. **跨行串成笔画轨迹**：按 x 方向重叠率 > 50% 把相邻行的游程链接起来。
3. **筛选可用区段**（三重约束）：
   - 与邻近笔画的**净空 ≥ 20 px**（保证测量窗不串扰到隔壁笔画）；
   - 宽度稳定在轨迹中位数的 85%–118%（剔除笔画交汇、端点收窄处）；
   - 连续长度 ≥ 50 行。
4. **分配码元**：从大到小尝试目标高度 h，取第一个能凑够 140 个码元的 h；**每条轨迹的码元数强制为偶数**（保证差分对不被拆散）。
5. **线性拟合中心线**：`x_center(y) = x_mid + slope·(y − y_mid)`，斜笔画靠这条线跟踪。

当前设计的推导结果：

| 指标 | 数值 |
|---|---|
| 码元总数 | 140（70 个差分对） |
| 使用笔画轨迹 | 11 条（2 条 R 竖干、2 条 R 碗侧壁、2 条 O 侧壁、A 双腿、W 对角线上段等） |
| 码元高度 | 14–15 px |
| 码元覆盖的笔画宽度 | 60–81 px（中位 63 px） |
| 覆盖总行数 | 2067 行 |
| 调制深度 d | 4 px（= 笔画宽的 6.3%） |

### 3.3 载荷编码

```
"13800138000"  →  int  →  37 bit  →  前置 3 个 0 凑 40 bit
              →  10 组 Hamming(7,4)  →  70 bit  →  70 个差分对
```

Hamming(7,4) 为纯 Python 实现，校验位在位置 1/2/4，数据位在 3/5/6/7：

```
p1 = d1^d2^d4      覆盖 1,3,5,7
p2 = d1^d3^d4      覆盖 2,3,6,7
p4 = d2^d3^d4      覆盖 4,5,6,7
伴随式 s = s1 + 2·s2 + 4·s4   →  直接给出出错位（1-indexed）
```

单比特纠错能力：每 7 bit 可纠正 1 位错误。这意味着**判决 BER 需低于 ~7% 才能保证整条消息大概率还原**。

### 3.4 为什么测「半高宽」而不是「墨量积分」

这是本方案鲁棒性的分水岭。两种特征在同等扰动样本下的对比（20 组，详见 6.2 节）：

| 特征 | 重度档 BER | 极限档 BER | 极限档成功率 |
|---|---|---|---|
| 墨量积分 `Σ(bg − I)` | 3.71% | 26.71% | 5%（1/20） |
| 半高宽（亚像素） | 0.00% | **0.29%** | **95%（19/20）** |

原因是：高斯模糊虽保积分，但测量窗是有限的，模糊会把能量扩散到窗外被截断；且积分正比于局部对比度，JPEG 块效应造成的对比度起伏会直接变成幅度噪声。而**高斯模糊是对称卷积，半高宽严格不变**；以 97 分位对比度归一化后，JPEG 块效应被大幅抑制。

最终采用的测量流程（`WatermarkDecoder.extract_widths`）：

```
逐行 y ∈ [y0+guard, y1−guard]:
  ① 以 x_center(y) 为中心开窗（宽 = 笔画宽 + 2d + 2×margin）
  ② bg = median(窗口左右各 5 个像素)        ← 局部背景，抗光照渐变
  ③ p = max(bg − I, 0)，3 点平滑            ← 抗 JPEG 块效应
  ④ ct = percentile(p, 97)                  ← 局部对比度（不用 max，抗噪点）
  ⑤ 若 ct < 18 → 该行被高光吃掉，弃用
  ⑥ 阈值 t = 0.5·ct，左右两侧线性插值求亚像素边缘
  ⑦ w(y) = right − left
对所有有效行取平均 → 该码元的宽度
```

## 四、四大模块

### 4.1 `WatermarkEmbedder`

- **字形母版**：直接取自设计稿——按颜色通道剔除红色标注线，二值化后裁到文字包围盒（706×140），以 1 bit PNG + base64 内嵌进源码（2.7 KB）。与设计稿的**逐像素二值差异为 0.002%**。运行时用 CUBIC 放大到 4× 制版尺度再阈值化，得到平滑的亚像素轮廓。
- **字形比例（实测）**：字高 142 px 基准下，A=0.993X、R=0.852X、O=0.930X、W=1.197X，总宽正好 5.0X，笔画 0.162X。A 顶点平台 0.18、字怀顶点 0.188、横杠 0.61–0.74；R 碗高 0.505、外沿最右 0.817；O 为超椭圆（外 n=2.05、内 n=3.0）；W 五顶点 (0.074,0)(0.30,1)(0.595,0)(0.88,1)(1.12,0)。
- **回退路径**：母版解码失败时，退回几何多边形构造（`_glyph_A/R/O/W`），保证代码在无母版数据时仍可运行。
- **无任何定位标记**：白底上只有 ARROW 五个字母。解码靠字形自身的几何自同步
  （五字母质心 / 凸包四角 / 二阶矩仿射 / 墨迹包围盒 四类候选，NCC 择优）。
- **嵌入**：复制 4× 掩膜 → 对每个码元逐行做**真实几何位移**（不是膨胀/腐蚀图按比例混合，
  那会产生半透明环带，让半高宽在 0 与 d 之间跳变）→ 渲染成灰度底版。
  位移量 `e(y) = sign·d·sin(πt)`，d = 1.8 px，码元两端 e=0，因此相邻码元之间没有台阶。

### 4.2 `CeramicCamSimulator`

把底版"印"到陶瓷上，再模拟手机微距拍摄。五类扰动串联：

| 环节 | 物理建模 | 参数范围（极限档） |
|---|---|---|
| (a) 油墨扩散 / 烧制形变 | 形态学膨胀/腐蚀（椭圆核）+ 印刷 MTF 高斯 σ=0.65 | 半径 −3.2 ~ +3.2 px |
| 承印层 | 陶瓷底色 246 + 低频斑纹 + 暗角；油墨色随机 46–82（不同批次深浅） | — |
| (b) 三维透视 | **针孔相机模型**：`u = X/(1 − Y·sin t)`，`v = Y·cos t/(1 − Y·sin t)`，再绕光轴滚转 | 倾角 24–30°，滚转 ±14° |
| (c) 釉面高光 | 1–2 个随机旋转高斯椭圆光斑，screen 混合拉向 255（局部过曝）+ 线性环境光渐变 | 强度 0.60–0.92，渐变 ±32% |
| (d) 失焦 + 运动模糊 | 高斯模糊 + 随机角度线性运动模糊核 | σ 2.2–3.4，核长 9–16 px |
| (e) 噪声 + JPEG | 泊松散粒噪声（gain 26）+ 高斯读出噪声；JPEG 有损压缩 | σ 7–12 灰阶，质量 28–50 |

> 透视用的是真正的单应（keystone），不是仿射缩放——倾斜 30° 时上下边宽度比约 0.79，与真实拍摄一致。

### 4.3 `WatermarkDecoder`

八步流水线，每一环都有兜底：

**⓪ 先定位、再解码（不再是"失败后补救"）**

真实拍摄里 logo 常常是白底卡片/标签贴在深色产品或屏幕上。此时形态学背景估计会把
四周的大片暗区当成墨迹，自同步直接失效——实测一张 1279×1706 的翻拍屏幕照片，
整幅解码失败，候选 NCC 仅 0.05。

所以解码入口先做**构图定位**，产出多条假设，各自完整解一次：

| 路径 | 适用构图 | 做法 |
|---|---|---|
| A `full` | logo 占满画面 | 整幅直接解 |
| B `plate#k` | logo 是白底标签贴在深色背景上 | 取最大的 k 个亮连通域（宽高比 2–6），填掉内孔、域外置白、裁包围盒后解 |

**择优规则不是"置信度高就赢"**，而是先看配准质量再过闸：
错误路径会把画面裁错，宽度测量全乱，`mean_conf` 反而虚高到 0.12，
但它的 `cc` 是 **0.000**。因此按 `(cc ≥ 0.85, mean_conf)` 的字典序比较。
实测照片1 若只按置信度择优会解成错误号码，加上 cc 闸门后正确回到 `40144815605`。

短路条件：整幅已经 `cc ≥ 0.95` 且 `mean_conf ≥ 0.030` 时直接返回，不再花时间定位
（干净印版、仿真样本都走这条，耗时无变化）。

**① 形态学背景差分二值化**
用大尺寸（≈0.15×短边）矩形结构元做**闭运算**估计"假如这里没印字会是什么样"，再取差分 `bg − g > 38`。闭运算会填平所有比结构元窄的暗结构（笔画），因此 `bg` 就是无墨背景。这一招对釉面渐变、局部高光、整体曝光全部免疫。阈值依次尝试 **38 → 26 → 18**。

**② 字形自同步（四类候选）**
底版上没有任何定位标记，几何基准全部来自 ARROW 自身。每次尝试产生若干候选单应：

| 候选 | 依据 | 适用 |
|---|---|---|
| A. 五字母质心 | 连通域质心 → 5 点超定单应（RANSAC） | 字母可分离时最稳，质心是全局积分量 |
| B. 凸包四角 | 整排墨迹凸包 → 主轴坐标系内 `approxPolyDP` 简化成 4 点 | 字母粘连时兜底 |
| C. 二阶矩仿射 | 墨迹协方差矩阵的特征分解对齐 | 天然含剪切，抗局部形变 |
| D. 墨迹包围盒 | 观测包围盒 → 设计包围盒的仿射 | 对干净印版即恒等变换 |
| E. **内孔质心** | 4 个内孔（O 内环 / 两个 R 字怀 / A 上三角）的质心 → 4 点精确单应 | **极端透视下最稳**：内孔被墨迹完全包围，质心不受外轮廓模糊与油墨胀缩影响 |
| F. **SIFT + RANSAC** | 模板与待测图的 SIFT 特征点匹配 → RANSAC 单应 | **与亮度、背景、构图完全无关**；缩放/旋转/透视/画面杂物都免疫。大图先降采样到长边 1400 再跑 |

**③ 候选单应 NCC 择优**
每个候选都用 **1/4 分辨率归一化互相关**打分（把候选矫正到标准坐标系后与模板比较），按分数排序，去重后最多保留 4 个起点。

候选 E（内孔质心）：极限档样本里，原有候选的 NCC 只有 0.44–0.48，内孔质心能到 **0.72**。

候选 F（SIFT + RANSAC）：这是 OpenCV 自带的标准定位方式，也是收益最大的一条。
它完全不依赖二值化，因此在"白底标签贴在深色屏幕上"这类构图上也能直接给出正确单应
（实测一张 1279×1706 的翻拍屏幕照片，logo 仅 428×129 px，SIFT 仍匹配到 27 个内点）。
加入后极限档 68% → **74%**、BER 9.86% → 7.49%，且因为 SIFT 一次命中，
反而**减少了触发粗搜抢救的次数**，极限档平均耗时从 3.28 s 降到 2.31 s。
可用 `WatermarkDecoder(use_sift=False)` 关掉做对照。

**④ ECC 亚像素精配**
`findTransformECC(MOTION_HOMOGRAPHY)`，半分辨率，先单应再回退欧氏。带采纳门限：相关系数 > 0.40、四角位移 < 24 px 才接受。多起点逐个尝试，取 cc 最高者；cc ≥ 0.88 立即停止。

**⑤ 粗搜抢救（cc < 0.80 时触发）**
在 **1/8 分辨率**上做「旋转 × 缩放 × 剪切 × 平移」四维粗搜（7×5×5 组合，`matchTemplate`），把偏出几度的解拉回正确盆地，再跑一次 ECC。代价是耗时从 0.4 s 涨到 2.4 s，所以只在必要时触发。

**⑥ 匹配滤波半高宽**（见 3.4 节）
逐行求亚像素半高宽 `w(y)`，用与嵌入端同形状的 sin 窗加权积分：`M = Σw·sin(πt) / Σsin²(πt)`，差分对相减得 `2·1.57·d ≈ 5.6 px` 的净信号。

**⑦ 差分判决 → 70 bit**

**⑧ 软判决最大似然译码 → 11 位数字**
Hamming(7,4) 每 7 bit 独立枚举 16 个合法码字，取与软信息相关最大者。相比硬判决 + 伴随式纠错，
一组内出现 2 位错时不会误纠（见 10.7 节）。

### 4.4 `BenchmarkRunner`

随机生成 50 组 11 位号码（首位非 0）→ 每组嵌入一次 → 在 5 档扰动下各解码一次 → 统计 BER 与完整解码成功率，输出终端表格、JSON 与曲线图。

## 五、关键工程决策（踩坑记录）

开发过程中有四个问题曾导致系统完全不可用，记录如下。

### 坑 1：二值化被釉面高光边缘污染（最致命）

**现象**：轻度扰动下 BER 43%，配准完全失效，单次解码耗时 31 s。

**根因**：最初用 `g / 高斯模糊` 做光照归一化再 Otsu。高斯模糊在高光边缘跟不上亮度变化，导致 `g/bg < 1` 的环带被判定为墨迹——产生了 **41728 个连通域**，最大的一块面积 474769 px 横跨半个画幅。凸包因此退化成整幅图像，锚点四边形变成 `[[4,0],[2599,0],[2593,1597],[0,1599]]`。

**修复**：改用**形态学闭运算估计无墨背景 + 差分阈值**。闭运算用 `(k,1)` 和 `(1,k)` 两个矩形核分离执行（矩形核的闭运算是可分离的），1300×800 上仅需 7 ms。修复后连通域从 4 万个降到 **9 个**（5 个字母 + 4 个锚点）。

**附带收益**：顺带消灭了 `keep[lab == i] = 255` 这个 O(组件数 × 像素数) 的循环，解码耗时从 31 s 降到 0.2 s。

### 坑 2：光照渐变把几何基准质心拉偏

> 这一坑发生在"还有四角锚点"的早期版本。锚点后来被整体去掉（见 3.x / 4.3），
> 但同一套质心定位逻辑现在用在五字母质心候选上，修复仍然有效。

**现象**：锚点残差最大 7.14 px，测量窗系统性偏移。

**根因**：质心权重用 `clip(bg − I, 0)`，`bg` 取窗口的 92 分位。窗口内有光照渐变时，背景暗侧也产生正权重，把质心拽向暗侧。

**修复**：改为 `thr = 0.5·(p2 + p90)`，`wgt = clip(thr − I, 0)`。只让真正的墨迹参与质心，背景整体被排除。残差降到 < 1 px。

### 坑 3：墨量积分在极限扰动下失效

**现象**：极限档 BER 22%（当时的设计与样本），成功率约 50%。

**修复**：换成半高宽（见 3.4 节）。在最终设计上复测，极限档 BER 从 26.71% 降到 0.29%，成功率从 5% 升到 95%。

### 坑 4：高光把几何基准冲淡到阈值边缘

> 同为"锚点时代"的记录。去掉锚点后，这一现象转化为"高光把字母边缘冲淡"，
> 三级阈值 + NCC 择优仍然保留，是当前版本的重要组成部分。

**现象**：spec ≥ 0.79 的样本全部失败，BER 50%，ECC 相关系数跌到 0.1–0.5。

**根因**：`img += g·amp·(255 − img)`，当 amp ≈ 0.78 时，58 灰阶的锚点被抬到 212，与 255 的背景只差 43——正好卡在差分阈值 38 的边上，锚点时有时无。

**修复**（三管齐下）：
1. 锚点从 16 px 加大到 20 px；
2. 三级阈值兜底（38/26/18）；
3. 候选四边形用低分辨率 NCC 择优。

极限档成功率：**50% → 90%**。

## 六、实验结果

### 6.1 压力测试主表

| 扰动等级 | 样本 | 总比特 | 错误比特 | BER | 成功数 | 成功率 | 平均置信度 |
|---|---:|---:|---:|---:|---:|---:|---:|
| 无扰动 clean | 50 | 3500 | 0 | **0.00%** | 50 | **100.00%** | 0.0384 |
| 轻度 light | 50 | 3500 | 2 | 0.06% | 50 | **100.00%** | 0.0380 |
| 中度 moderate | 50 | 3500 | 9 | 0.26% | 50 | **100.00%** | 0.0361 |
| 重度 heavy | 50 | 3500 | 37 | 1.06% | 50 | **100.00%** | 0.0310 |
| 极限 extreme | 50 | 3500 | 262 | 7.49% | 37 | **74.00%** | 0.0257 |

**解读**：置信度随扰动单调下降（0.0384 → 0.0257），前四档均未出现失败，极限档失败 13 次。

极限档的 13 个失败样本，用仿真器的精确几何参数（真值单应）矫正后逐个复核：**6 个**的 BER
从约 50% 掉到 5–10%（配准问题），**7 个**即使几何完全正确 BER 仍有 3–24%（信号不足）。
也就是说极限档是配准与信号各占一半，不是单一瓶颈。配准这一半已经靠「内孔质心候选」和
「SIFT + RANSAC」改善（见 4.3 候选 E / F）；信号这一半受限于调制幅度，加大就会破坏隐蔽性。

### 6.2 消融对比

**特征选择**（同一批 20 组号码、同一批扰动样本，仅替换判决特征）：

| 判决特征 | moderate | heavy | extreme |
|---|---|---|---|
| **半高宽（默认）** | BER 0.00% / 20-20 | BER 0.00% / 20-20 | **BER 0.29% / 19-20** |
| 墨量积分 | BER 0.21% / 19-20 | BER 3.71% / 13-20 | BER 26.71% / **1-20** |

半高宽在极限档把成功率从 **5% 拉到 95%**，这是整个系统最关键的一次技术选型。重度档的差距也很明显（100% vs 65%）。

**ECC 精配**（同 20 组号码、同 seed=7）：

| 配置 | clean | light | moderate | heavy | extreme |
|---|---|---|---|---|---|
| 完整系统 | 100% | 100% | 100% | 100% | **95%（19/20）**，BER 3.14% |
| `--no-ecc` | 100% | 100% | 100% | 100% | 90%（18/20），BER 3.36% |

**结论修正**：在锚点迭代精配（第 ⑤ 步）做到亚像素级之后，ECC 的边际收益已经很小——极限档只贡献约 5 个百分点。它保留下来主要是作为极端情况下的兜底，而不是性能来源。早期版本（锚点质心未修正、残差达 7 px 时）ECC 的作用要大得多。

**二值化方案**（早期版本的对照）：

| 配置 | light | moderate | heavy | extreme |
|---|---|---|---|---|
| 形态学背景差分（当前） | 100% | 100% | 100% | 90% |
| 归一化 + Otsu（早期） | 0% | 0% | 0% | 0% |

早期方案在轻度扰动下配准就已完全失效，属于"能不能用"级别的差异，而非"好不好用"。

### 6.4 性能调优（哪些有效、哪些被否掉）

解码耗时由三块构成（以 clean 档为例，比例稳定）：SIFT 定位 ≈ 26%、ECC 精配 ≈ 37%、
逐行宽度测量 ≈ 37%。针对三块各试了优化，结论如下：

| 优化 | 效果 | 结论 |
|---|---|---|
| SIFT 大图降采样到长边 1400 再跑 | SIFT 从 0.50 s 降到 0.13 s | ✅ 采纳 |
| ECC 迭代 60 → 30（eps 1e-6） | 耗时降 10–25%，精度不变 | ✅ 采纳 |
| 改 SIFT 降采样目标到 1000 | 内点数反而更多，但极限档 74%→66% | ❌ 回退 |
| 宽度测量向量化（remap + numpy） | 快 6 倍（0.19 s → 0.03 s） | ❌ 回退 |
| SIFT 分数高时跳过二值化候选 | 省 0.18 s | ❌ 回退 |

**后三项为什么回退**（都是实测踩出来的）：

- **向量化测量**：原实现按**整数列**切窗口，向量化用 `remap` 做亚像素采样会引入双线性
  模糊，半高宽产生 0.3–0.5 px 偏差（调制只有 1.8 px）。修正为整数列采样后偏差降到
  0.4 px 以内，但中度档仍从 100% 掉到 96%。精度优先，保留逐行实现。
- **SIFT 短路**：SIFT 的 H 偶尔"NCC 看着很高、实际偏一点"，跳过其他候选就失去了让
  ECC 纠正的机会，中度/重度各掉 1 个样本。
- **SIFT 降到 1000**：内点数更多（47 vs 38）但几何精度更差——**内点数不等于精度**，
  这是个容易踩的坑。

最终保留的两项是纯工程优化（不改变任何数值路径），精度与优化前完全一致：
clean/light/moderate/heavy 均 100%，极限 74%。

### 6.5 代码评审修复与提速（结果不变）

外部评审逐行核对了实现，指出若干重复计算与逻辑缺陷。逐条核实后**全部属实**，已修复并回归验证。

**四处逻辑缺陷**

| 位置 | 问题 | 后果 |
|---|---|---|
| 二阶矩候选 | 解出的是"模板→照片"，却按"照片→模板"入池 | 该候选恒为无效解，白占一个起点 |
| 抢救分支 | `warped` 已替换但 `ecc` 分数没换 | 候选之间拿"旧图的分数"比"新图的画质" |
| `bits_to_payload` | 37 bit 越界时 `v %= 1e11` | **任何垃圾都能吐出一个合法 11 位号码**，只能靠置信度区分 |
| `decode_payload` 返回值 | 越界被静默折回 | 同上 |

第三、四条对验真场景最危险，已改为越界返回 `None`，并在结果里给出 `payload_valid`。

**三处重复计算**

| 位置 | 问题 | 处理 | 实测 |
|---|---|---|---|
| `_find_transforms` | 三个阈值各重算一遍缩图+模糊+两次大核形态学 | 差分图算一次，只重复阈值 | — |
| `_row_width` | `np.percentile` 每次排序 | 换成 `np.partition`，逐位等价 | 190 ms → **102 ms** |
| `--decode` 入口 | 先建整套嵌入器/仿真器，再重建一次解码器 | 解码分支提前返回 | 两张照片 3.5 s → **1.86 s** |
| `import arrow_wm` | 注释称"延迟导入"，实际立即加载 matplotlib | 改为首次出图才导入 | 0.90 s → **0.44 s** |
| `batch_decode --save-figs` | 出核验图时再完整解码一次 | 复用已算好的结果 | 每张省一次解码 |

宽度测量改成向量化版本（快 6 倍）**没有采纳**：原实现按整数列切窗口，`remap` 的亚像素采样
会引入双线性模糊，半高宽偏 0.3–0.5 px（调制才 1.8 px），中度档从 100% 掉到 96%。
最终只做了逐位等价的算子替换，特征最大差 **0.000**。

**判据修正：mean|conf| → 码字裕度**

评审还指出"`ok=True` 不等于号码可靠"。实测确认：**纯随机噪声有 6/14 被 mean|conf|≥0.020
判为"有码"**（噪声 0.016–0.025，真码 heavy 才 0.030，只差 1.2 倍）。

改用**码字裕度**——每个 7 bit 组里最优码字与次优码字的相关差，除以软信息标准差：

| 样本 | mean\|conf\| | 码字裕度 |
|---|---|---|
| 真码 clean / heavy / extreme | 0.038 / 0.030 / 0.024 | **5.28 / 4.35 / 2.04** |
| 随机噪声（8 张） | 0.016–0.025 | 0.88–**1.40** |
| 无码印版 / 无码+扰动 | 0.004 / 0.007 | 0.96 / 1.35 |

门限取 1.8：误报从 **6/14 降到 0/14**，真码全部保留。

**回归**

修复后 50 组压测：clean/light/moderate/heavy 均 **100%**，extreme **74%**（BER 7.14%），
与修复前逐项一致。四张实拍照片解码结果不变。

## 八、参数说明与调优

| 参数 | 当前值 | 说明 | 调整建议 |
|---|---|---|---|
| `MOD_DEPTH` | 1.8 | 单侧边沿正弦偏移（px） | 实测 1.5~3.0 在轻/中/重度下成功率相同，1.0 会掉；取接近下限的 1.8 换取最平滑边沿 |
| `MIN_CLEARANCE` | 20 | 码元与邻笔的最小净空 | 调小能增加容量（码元变矮），但测量窗易串扰 |
| `CELL_MARGIN` | 10 | 测量窗余量 | 与 `MOD_DEPTH` 联动，需满足 `净空 ≥ 2d + margin` |
| `N_BITS` | 70 | 编码后比特数 | 必须为 7 的倍数（Hamming 分组） |
| `T_WEIGHT` | 0.175 | 笔画粗细（占字高比例） | 调粗能提升鲁棒性，但字怀变小、容量下降 |
| 布局宽度容差 | 22% | 码元中位宽度允许偏离全局中位数的比例 | 放宽到 25% 会放进 A 顶点并笔区的坏点（恒定误码） |
| `use_soft_decode` | True | 软判决最大似然译码 | 关掉退回硬判决，极限档 66% → 58% |

**关于"隐蔽性"的说明**：`MOD_DEPTH = 1.8` 时，相邻码元的笔画宽度差为 3.6 px，在 71 px 宽的笔画上是 5%。5× 放大图中仍能看到微波，换算到物理尺度是 **±0.018 mm**——在 2.2 cm 宽的 logo 上，正常视距（30 cm）下远低于人眼分辨极限（≈0.1 mm）。若要求外轮廓绝对笔直，请改用内孔载体（第十章）。

## 九、局限与后续方向

### 当前局限

1. **极限档的失败是"配准"与"信号"各占一半**。用真值单应（仿真器的精确几何参数）
   矫正后逐样本复核：17 个失败样本里 6 个 BER 从约 50% 掉到 5–10%（配准问题），
   其余 11 个即使几何完全正确，BER 仍有 3–24%（信号不足）。
   配准这一半已经用"内孔质心候选"改善（见 4.3 候选 E）；信号这一半受限于
   调制幅度——再加大就会破坏隐蔽性，这是无标记方案的固有代价。
2. **外轮廓的边沿微波在放大下可见**。±1.8 px 的正弦起伏在 5× 放大图上仍能看出波浪，
   这是 70 bit / 2000 px 的信息密度决定的（每 bit 只有约 28 px）。
   第十章给出了换载体（内孔）的方案：外轮廓逐比特不变，代价是极限档成功率下降。
3. **未做真实拍摄验证**。当前全部结果基于物理信道仿真，真实陶瓷样片的墨滴扩散、
   釉层折射、手机 ISP 锐化都可能带来仿真未覆盖的失真。
4. **单帧解码**。没有利用多帧融合，若能连拍 5–10 帧做时域平均，极限档还有提升空间。
5. **内孔版的尖角区域偏弱**。A 三角孔与 R 字怀的尖角在模糊下会把径向位移抹平，
   是内孔版极限档掉到 30% 的主要原因。

## 十、载体对比实验：外轮廓 vs 内孔

### 10.1 动机

第九章列出的第一条局限是"边缘起伏在放大下可见"。这一条背后有明确的生理学原因：

**游标锐度（Vernier acuity）**。人眼分辨两个点的距离约 0.1 mm，但判断"一条边直不直"的
灵敏度高出一个数量级——视觉系统对**共线性破坏**极其敏感。因此把 70 bit 写成外轮廓上的
±1.8 px 正弦起伏时，即使物理尺度只有 0.018 mm，在笔直边的衬托下仍然刺眼。

换载体的目标很明确：**外轮廓一个像素都不动**，把信息搬进字母内部。

### 10.2 两种载体

| | 边缘版 `arrow_wm.py` | 内孔版 `arrow_inner.py` |
|---|---|---|
| 信息载体 | 笔画**外轮廓**的宽度调制 | 4 个**内孔**边界的径向调制 |
| 调制方式 | 逐行水平膨胀/腐蚀，正弦窗 `d·sin(πt)` | 内孔多边形按 `r(θ)+δ(θ)` 重绘 |
| 外轮廓 | 起伏 ±1.8 px | **逐像素不变** |
| 码元布局 | 由笔画轨迹自动推导，140 个 | 按内孔周长分配，48/32/32/28 |

### 10.3 容量核算

四个内孔在 1x 底版上的周长：O 内环 855 px、两个 R 字怀各 583 px、A 上三角 504 px，
合计 **2525 px**。140 个码元 → 平均每格 **18 px**，与边缘版的码元高度（约 19 px）相当。

内孔按周长比例分配，且每个孔分到的码元数必须为偶数（保证差分对不跨孔）：
48 + 32 + 32 + 28 = 140。

### 10.4 硬指标：外轮廓零改动

把四个内孔的外接框（各留 4 px 余量）遮掉，比较其余区域的灰度：

| 版本 | 孔外最大灰度差 | R 竖干左边缘的亚像素位置 | 峰峰值 |
|---|---|---|---|
| 边缘版 | 197 | 509.66 ~ 513.32 | **3.66 px** |
| 内孔版 | **0.0** | 511.49 ~ 511.49 | **0.00 px** |

也就是说内孔版的外轮廓与原图**逐比特相同**，不是"差异很小"，是"完全没有"。
`12_carrier_cmp.png` 第二行是 R 竖干外轮廓的 6× 放大，第三行是 O 内环的 5× 放大，
第四行是同一条边的亚像素位置曲线——原图与内孔版两条线完全重合。

### 10.5 鲁棒性（每组 20 样本，seed=6000）

| 档位 | 边缘版 D=1.8px（n=50） | 内孔版 D=2.2px（n=20） |
|---|---|---|
| 无扰动 | 50/50 · 100% · BER 0.00% | 20/20 · 100% · **BER 0.00%** |
| 轻度 | 50/50 · 100% · BER 0.06% | 20/20 · 100% · **BER 0.00%** |
| 中度 | 50/50 · 100% · BER 0.26% | 20/20 · 100% · **BER 0.00%** |
| 重度 | **50/50 · 100%** · BER 1.06% | 18/20 · 90% · BER 1.57% |
| 极限 | **37/50 · 74%** · BER 7.49% | 7/20 · 35% · BER 15.00% |

> 边缘版为 50 组终版数据（与第一章/6.1 节一致），内孔版为 20 组。两者用同一套载荷生成逻辑。

两个现象值得注意：

1. **内孔版前三档的原始 BER 是 0.00%**，而边缘版在布局修复前是 1.43%（修复后 0.00%）。原因是边缘版的布局里
   不可避免地存在少数"宽度沿纵向不稳定"的码元（W 的 V 形交汇处），内孔版的边界
   沿弧长均匀，没有这类系统性坏点。
2. **内孔版在极限档明显更弱**（30% vs 60%）。内孔边界是闭合曲线，可用的"有效边"更短，
   且 A 三角孔与 R 字怀存在尖角，模糊会在角上把 ±2.2 px 的位移抹平，等效信噪比低约 2 dB。

### 10.6 内孔调制深度：2.2 → 6.0 px

早期内孔版取 D = 2.2 px，依据是一组 n=20 的小样本实验（heavy 档 18/20）。
但 2.2 px 在极限档明显不够用，而深度是唯一能直接买到信噪比的杠杆。

**对照**（同一套压测、同一批载荷与扰动，n=50）：

| depth | clean | light | moderate | heavy | extreme | extreme BER |
|---|---|---|---|---|---|---|
| 2.2 px（原默认） | 100% | 100% | 100% | 96% | **32%** | 14.57% |
| **6.0 px（现默认）** | **100%** | **100%** | **100%** | **98%** | **60%** | **6.00%** |

极限档从 32% 提到 60%（翻倍），BER 从 14.57% 降到 6.00%，重度档同时从 96% 升到 98%。
极限档正是手机实拍最容易掉进去的那一档，所以这笔交易划算。

取 6.0 而不是更深的理由：

1. 边界起伏 ±0.060 mm，2.2 cm 实物下仍低于人眼分辨极限（≈0.1 mm），客户比对设计稿看不出；
2. 打印 1200 dpi 时调制幅度 = **2.84 个墨点**，远高于实测下限（每码元 ≥7 点）；
3. **外轮廓仍逐像素不变**——孔边界 ±6 px 之外的灰度差在所有深度下恒为 0（逐像素核验）。

代价是内孔边缘的波纹更明显，8× 放大下能看出来；整幅尺度基本不可辨。

### 10.7 顺带的解码端改进：软判决最大似然

做这组实验时发现一个与载体无关的浪费：Hamming(7,4) 之前用的是**硬判决 + 伴随式纠错**，
一组内出现 2 位错时会**误纠**成另一个合法码字（数据静默出错），而每比特的置信度信息
被完全丢掉了。

`decode_payload_soft()` 改为在 16 个合法码字里取相关最大者（软判决 ML）。只改解码端，
不改变任何视觉与嵌入格式：

| 档位 | 硬判决 | 软判决 | 增益 |
|---|---|---|---|
| 重度 | 48/50（96%） | **49/50（98%）** | +2 个百分点 |
| 极限 | 29/50（58%） | **33/50（66%）** | **+8 个百分点** |

这是纯解码增益，不改变任何视觉与嵌入格式，边缘版与内孔版都已默认启用
（`WatermarkDecoder(use_soft_decode=True)`，可关掉做对照）。

### 10.8 结论与建议

| 场景 | 推荐 |
|---|---|
| 客户质检会看外轮廓、要求"和设计稿一模一样" | **内孔版**（外轮廓逐比特相同，重度 90%） |
| 要求最高解码成功率、能接受放大后可见的边沿微波 | **边缘版**（重度 95%、极限 60%） |

两条路线的取舍本质是：**把有限的信息量放在"眼睛最敏感的地方"还是"最不敏感的地方"**。
内孔版把代价从外轮廓转移到了 0.1–0.3 mm 的小孔里，这是目前能做到的最优折中。

若要把内孔版的重度成功率拉回 95% 以上，可行方向有两个：把 A 三角孔与 R 字怀的尖角
区域从码元分配中剔除（牺牲约 10 个码元容量），或改用 BCH(63,45) 之类更强的前向纠错。

## 附录：核心公式速查

**透视投影（针孔模型，平面绕水平轴倾斜 t）**
```
u = X / (1 − Y·sin t)
v = Y·cos t / (1 − Y·sin t)
```

**差分判决**
```
bit_i = 1  if  w[2i] − w[2i+1] > 0  else 0
conf_i = (w[2i] − w[2i+1]) / (w[2i] + w[2i+1])
```

**亚像素边缘（半高宽）**
```
ct = percentile(p, 97)          # 局部对比度
t  = 0.5 · ct                   # 半高阈值
x_left  = l − 1 + (t − p[l−1]) / (p[l] − p[l−1])
x_right = r + (p[r] − t) / (p[r] − p[r+1])
w = x_right − x_left + 1
```

**Hamming(7,4) 伴随式**
```
s = s1 + 2·s2 + 4·s4      # 直接等于出错位序号（1-indexed），0 表示无错
```
